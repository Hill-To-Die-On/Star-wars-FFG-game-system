# Content review drafts and source evidence

`npm run review:content` prepares a local, archive-bound inventory. It is not a requirement to classify every technical literal independently. The standalone page supports source-level evidence, individual exceptions and a complete draft export.

The current listing phase is **Beta**, selected by The User on 2026-10-13. Phase metadata does not change a reviewed ZIP's hash or saved answers. Earlier Alpha filenames remain usable; the page identifies an earlier archive designation separately and exports a Beta draft. Changing the text inside packaged documentation requires a new archive and an explicit reconciliation.

The default authorship queue contains prepared in-module and listing text. Changelog, code, configuration and technical package documentation are outside that queue under Foundry AI policy section 4.4 and use the maintenance attestation. Repository material that is not shipped is absent from the inventory. Promotional copy remains subject to the marketing rule wherever used. Reference metadata/licences are grouped for rights review. Inline literals use source context to separate selectors, property access, compared constants and localization keys from prepared wording; unknown or mixed occurrences remain in the prepared queue. Word count alone never exempts a UI label. All routes are review purposes, not approvals.

Schema identifiers, format names, record IDs and other recognized machine fields are technical audit records. They never display individual decision, evidence or replacement inputs, even in the complete inventory. Previously saved answers remain readable and export unchanged. Dataset and asset permissions are shown by file/category and recorded through the human gates or optional source evidence rather than thousands of per-value forms. Source/category choices retain the selected review purpose; they cannot silently switch the prepared-copy queue to the complete inventory. The audit is an explicit view choice. This review-tooling correction does not change installed behavior or the wiki's candidate guidance; no additional wiki source edit is needed for it.

Single- and two-word interface labels share one statement in **Single- and two-word interface labels**. Its expandable, searchable member list retains exact wording and every source occurrence. The default prepared-copy queue omits bundled labels, while explicit rewrites, replacements and other individual classifications stay visible. **Show individual short labels for exceptions** and member-list buttons allow per-entry edits. The bundle covers plain short interface catalogue/CSS/SVG wording and runtime literals with known label context, including other occurrences of that same runtime text. Markup, dynamic text, rules, listing copy and unknown runtime literals do not qualify merely by being short. Longer text remains separate.

The exported `labelReview` records the statement, reviewer, state and exact member IDs. Previous drafts gain an unfinished empty statement; no human approval is inferred. A recorded statement can supply shared provenance evidence for ordinary label decisions, but cannot erase a rewrite, replacement or other classification. Imports reject mismatched coverage as well as a different archive. If a stored label list expands, the earlier statement and all answers are retained with pending coverage and a browser backup under `<key>.before-label-bundle-update`; the expanded list needs recording again. Ellipses and separator dots on controls do not create extra words. The archive hash, every text ID and the existing browser storage key are unchanged. This is unshipped review tooling; installed behavior and wiki guidance do not change.

The User requested **scan and flag exceptions** on 2026-10-13. Text without a saved decision displays `human-origin` by default; change it to **Needs review** (`pending`) when an exception needs attention. Existing saved decisions, including pending flags, always take precedence. The default rendered view and collapsed optional notes reduce routine form controls; source/rendered/both views remain available. Export records `defaultDecision: "human-origin"` and `defaultSelectionIsSignOff: false` without filling thousands of per-entry approvals. `submissionReady` remains false.

Exact string duplicates appear once across categories. Case, whitespace and markup are not normalized. Each card retains every original ID and source occurrence, and the short-label inspector also shows each wording once. A shared edit records the same answer under the matching prepared-copy IDs; technical and rights records remain read-only. Different existing answers or isolated flags/replacements stay editable as individual source exceptions. An explicit source-exception edit targets only that original ID. Identical runtime copies of a known short UI label join its shared statement, while marketing, rules prose and audit-only data do not join that bundle just by matching its text. This unshipped review UI changes no installed system behavior or wiki guidance.

- **Missing-evidence items — shared sign-off** bundles explicit human-origin and technical-only decisions that lack a note. Its editable suggested declaration is unsigned until **Confirm shared missing-evidence statement** is clicked with reviewer identity and a nonempty statement. The export retains `missingEvidenceReview` with the reviewer, evidence, state and exact original IDs and classifications. It supplies shared evidence without altering individual answers or approving untouched defaults. Rights decisions, rewrites and replacements remain separate. Changed classifications or replacement text cannot inherit the earlier statement. Previously confirmed members remain inspectable after other source/label evidence is recorded. Editing the statement returns it to pending. Old drafts acquire an empty, pending bundle without losing answers. This unshipped review tooling has no installed behavior or wiki impact.
- The **Review confirmations** links at the top jump to the shared missing-evidence section or the **Single- and two-word interface labels** section. A saved short-label note is confirmed by clicking **Confirm short-label review**; entering text alone leaves it pending. The two confirmations remain separate, and neither declares submission readiness.
- **Export review JSON** always saves a structurally valid unfinished draft, including reviewer, listing, gates, source notes, per-record decisions and replacements. Missing evidence is listed in `reviewIssues` and never prevents a backup. `submissionReady` is always false.
- **Check recorded decisions** identifies changed decisions that lack reviewer or evidence. Each issue links to its record. Pending inventory rows are allowed and are not automatically approved.
- **Shared evidence by source** groups by exact file and category. Record a source, permission or authorship note once for that scope. An individual decision can refer to shared evidence when every occurrence is covered; explicit exceptions and replacements are retained. Source notes do not classify the underlying entries as human-authored or certify legal compliance.
- Keep code maintenance distinct from authorship of displayed text, including single-word UI labels. Mixed runtime source contains both. Reference dataset provenance can be described once with its permission scope rather than repeated on IDs, names and table metadata.

The existing `star-wars-ffg.review.<archiveSha256>` storage key and schema version 1 remain compatible with previous unfinished browser drafts. Imports reject another archive, unknown entries, decisions or source scopes. Before a valid import, the current draft is retained under `<key>.before-import` when storage is available.

The generator, workflow scripts, tests and this development note are not shipped in the system ZIP. Regenerating only review metadata/HTML from an unchanged archive leaves the package hash and every text ID intact. Replacements to shipped content require a new archive and the release review described in `docs/alpha-listing.md`.

The Beta phase change updates candidate wiki source labels alongside the roadmap and README. Publication remains a separate operation coordinated with the final release review; technical documentation does not require prepared-copy authorship sign-off. The public release is still 0.3.0.
