# GM quick start

This guide is for a normal human-GM game. Director of Realms is optional. Keep the relevant books available: a reference entry or a checked advancement graph does not mean every described effect is automated.

## Prepare a world

1. Install the system from the release manifest and create a world using Star Wars FFG. Start with no optional modules; add Dice So Nice after basic sheets and chat work.
2. Open the Settings sidebar and select Transaction authority for this GM browser. Confirm that previous transaction tabs have stopped. Repeat after reloading or handing over to another GM; other GM tabs can view without processing changes. [Authority and interrupted-request recovery](security-authority.md)
3. Open Configure Settings → Star Wars FFG → Campaign rules & adventure state. Enable the intended rule lines and choose the story mechanics separately. All three rule lines are enabled by default; adding a line does not grant another starting package.
4. Open Owned books and select the sources available to the table. The Reference catalogue searches the bundled database without a private import. Populate compendiums only when native world references are wanted.
5. Choose the sheet/interface theme, compact dice tray and turn-management policy. A theme is cosmetic. Decide whether players can add/reset turn allowances or whether those changes are GM/automatic only.
6. Give each player ownership of their character and access to the intended scene. Verify the scene from a separate player login. Do not assume a GM-visible map or token is visible to players.
7. Open Help & rules coverage for supported workflows and learned-effect details. For a private source library, export the GM source key before clearing browser storage or moving to another browser.

## Create the party

Create a Character actor and use its Manual creation or Guide me controls. Species, career and specialization come from the campaign-filtered database. Review the exact free ranks, starting-resource choice, equipment and XP before applying the draft. Handle cited species exceptions explicitly. Ready for play finishes the creation phase after outstanding reviews.

The GM may enable the homebrew identity override for non-catalogue species, careers, models or manufacturers. A homebrew label does not supply missing mechanics. Review those statistics before play. [Creation guide](character-creation.md)

Create a Vehicle actor and select its model through the searchable field. Check any incomplete profile or unverified loadout before combat. Use Crew & Passengers to assign or generate reviewed crew; checks use the assigned actor's skills. A renamed ship retains its model identity. [Crew guide](vehicle-crew.md)

## Run an encounter

Agree the intent before asking for a roll. For combat, choose the acting participant's initiative slot, select the source and target, and review range, line of sight, weapon, gunner and firing/defence face. Send dice to pool opens the adjustable pool; it does not itself resolve the attack.

Review missing source information and situational modifiers, then roll once. Inspect success/failure and the independent narrative symbols. Approve narrative spending through the chat workflow. Apply damage/recovery through Combat resolution after checking its preview; narrative approval alone does not apply those effects.

Criticals, conditions, unencoded qualities and cross-scale damage require their cited rule or an explicit table ruling. Recording a condition is not confirmation that its modifiers have been applied. Use Tabletop history for reversible changes; a stale undo refuses to overwrite newer values. [Tabletop workflows](tabletop-workflows.md)

## End a session

Review XP, credits, enabled story-resource adjustments and downtime notes in Session wrap-up. Review recipients and amounts before applying. If some recipients fail, inspect the named successful recipients and histories before retrying. Equipment rewards and automatic story/downtime triggers remain manual.

Save a world backup and keep private assets plus the source-key backup recoverable. Test restoration in a separate world before relying on the backup. For a support request, Help & rules coverage provides an inspectable diagnostic JSON without names, chat, keys or source notes.

## Before adding Director of Realms

Complete the same table workflow without DoR first. Configure a supported provider separately, review what private content may be sent, and retain GM approval for missing mechanics. Fully AI-led campaign acceptance is a separate gate. [DoR integration](director-of-realms.md)
