# Private book-art catalogue for Director of Realms

The local inventory covers the 66 held PDFs (5,764 PDF pages) by source-file hash, book title and PDF page. It records isolated raster placements separately from full-page scans. Small repeated decoration is counted but excluded from story-art suggestions. The private catalogue is `.local/book-art/catalogue-v1.json`; source PDFs, extracted pixels, absolute source paths and copied book prose are not in the released system.

The completed private pass covers 59 normalized book titles across those 66 source scans. All 5,764 pages received region triage, yielding 5,108 candidate regions; all 2,302 deduplicated isolated or sizeable raster placements received a separate visual classification, with 833 marked as possible story art. Together they form 7,410 provenance-linked visual records. After story-art, text and GM-label flags, **844** are currently unflagged candidates for GM inspection. A PDF text-layer check caught 483 text overlaps missed by vision. The page review queue still has 1,912 pages where vision found no region, reached its eight-region limit or discarded an invalid box. These counts describe scan coverage, not a verified exhaustive art list or player-safe images.

Artwork on a flattened page needs a region crop before it can be offered as an image. The resumable local vision pass stores a short visual label, type, normalized crop box, and flags for printed text and possible GM labels. These are **unverified candidates**. A page without a detected region remains in the catalogue's review queue; a model result is not proof that no art is present. PDF page numbers are kept distinct from printed page numbers, which remain unknown until checked. Same-title scans are source copies of one book, not different editions.

## Owned-book use

The GM's **Owned books** setting is the gate. `game.system.api.directorOfRealms.getOwnedBookSelection()` returns the configured titles. `getBookArtCandidates(privateCatalogue, { query, book, kind, page, pageSize })` searches only exact normalized titles in that owned selection. It returns short labels and page provenance without local file paths. Model-rejected images are hidden by default but can be inspected with `includeRejected: true`. Every result is GM-only and `playerSafe: false`; it does not choose a scene or show artwork to players. Unregistered adventures and GM kits are included in the private catalogue; the GM can enter their exact titles in **Additional owned books** before querying their art.

For selected books, the private `.local/book-art/export-for-dor.py --book "Exact owned title"` command prepares candidate crops and an `import-manifest-v1` per source under `.local/book-art/dor-imports/`. Use a fresh, empty `--out` directory for each selected-book export so older assets cannot remain beside a new selection. `--dry-run` reports counts without rendering. It excludes regions flagged with text or GM labels and skips crops that overlap selectable PDF words. Image-only scans have no text layer for that safeguard. The output follows DoR's existing `director-of-realms/imports/` manifest shape, which indexes imported images as GM-only; it has not been installed into a Foundry world. A GM must inspect each crop and approve any player-facing version or scene use. No source art is distributed with this system.

A local *Cyphers & Masks* validation export used its two held source scans: 14 candidates reached crop review, three overlapped selectable text, and 11 image files were written with matching manifests and only the selected book in the private catalogue. One exported crop was visually checked. Reusing the same nonempty export directory was correctly refused. The temporary validation images were removed afterward; the private catalogue and resumable scan results remain.

The remaining DoR work is to load a selected private catalogue, present a GM review UI, apply the selected book list during DoR asset retrieval, and verify an actual story scene. The broader DoR adventure-art intake, map preparation and Surveyor handoff remain open on the canonical roadmap.
